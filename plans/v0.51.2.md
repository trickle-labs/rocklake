# v0.51.2 plan: connection lifecycle

## Scope

Make admission, session state, idle timeout, and shutdown behavior explicit and
enforced. Preserve the supported wire behavior for accepted connections.

## Outcomes

- The server reserves session capacity before it creates a long-lived
  connection task.
- A connection above capacity receives a prompt PostgreSQL error. The default
  overload code is SQLSTATE `53300`.
- `idle_connection_timeout` closes an inactive connection in the server.
- Shutdown stops new connections, rejects new queries, drains in-flight queries,
  and closes idle sockets within the configured policy.
- Session metrics distinguish `connections_open`, `connections_idle`, and
  `queries_in_flight`.
- Existing session metric names remain deprecated aliases for two minor
  releases, or the release documentation contains an equivalent dashboard
  migration.
- `stream_queue_depth` and `max_buffered_rows` stop appearing in generated
  examples if the runtime does not enforce them. The server continues to accept
  them, emits one deprecation warning per startup or config check, and documents
  their lack of independent effect until the compatibility window ends.

## Implementation choices

Use a semaphore permit or equivalent reservation that is acquired before task
creation and released when the connection closes. Do not create an unbounded
waiting-task population. A bounded admission queue is allowed only with a
depth metric and wait timeout.

Keep the idle timer on the connection activity path. A connection with an
active query is not idle. A shutdown drain must not wait for idle sockets.

Keep compatibility aliases in the metric exposition during the declared
window. Record the migration in `COMPATIBILITY.md` and the monitoring guide.

## Black-box checks

| Scenario | Setup | Expected result |
|---|---|---|
| Capacity rejection | Set the session limit to one and open two connections. | The second connection is rejected promptly with SQLSTATE `53300`. |
| Idle timeout | Set a short timeout and leave an authenticated connection idle. | The server closes the connection after inactivity. |
| Active query is not idle | Set a short timeout and run a query longer than the timeout. | The active query is not closed as an idle session. |
| Shutdown with idle socket | Open an idle connection, then request shutdown. | The socket closes without extending the query drain. |
| Shutdown with active query | Start a query, then request shutdown. | New queries fail and the active query drains within the policy. |
| Deprecated configuration | Load a config containing an inert public setting. | Startup succeeds, emits one warning, and the generated example omits it. |
| Metric migration | Collect metrics during an open, idle, and active session. | New metrics are correct and old names remain documented aliases. |
| Cancellation while waiting | Saturate admission and cancel a waiting query. | The permit remains available for the next query. |

## Exit conditions

Run network tests for capacity, timeout, drain, shutdown, and cancellation.
Parse the metrics exposition and verify that all session gauges are
non-negative and internally consistent. Run the previous-release upgrade and
backup-restore checks.
