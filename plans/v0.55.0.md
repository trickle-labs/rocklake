# v0.55.0 plan: managed catalog registry and lifecycle

## Delivered

- Added a dedicated SlateDB-backed registry with version markers, immutable
  audit entries, generation/CAS mutation retries, lifecycle states, and
  deletion tombstones.
- Added idempotent local catalog lifecycle commands for create, register,
  rename, mode changes, disable, enable, and route-only removal.
- Added registry initialization, status, verification, local backup/restore,
  and v0.54 static-route migration commands.
- Added registry-backed server startup with immutable route generations and
  static emergency read-only recovery.
- Kept registry, catalog, and data prefixes disjoint and excluded raw secrets
  from registry rows and diagnostics.

## Verification

```bash
cargo fmt --all -- --check
cargo test -p rocklake-router
cargo test -p rocklake-pgwire --test v046_cli_tests
```

Registry removal only detaches routing. Physical catalog and data deletion,
remote management APIs, cross-catalog transactions, authorization, quotas, and
multi-node writer routing remain out of scope.
