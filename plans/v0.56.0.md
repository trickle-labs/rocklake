# v0.56.0 plan: multi-principal authorization, quotas, and isolation

## Delivered

- Added stable principal IDs, role/group metadata, opaque SCRAM verifiers, and
  catalog grants persisted in the managed registry or static TOML.
- Added fake-verifier authentication for unknown users and authorization after
  authentication, before route disclosure or catalog opening.
- Bound principal identity, grant generation, stable catalog ID, route
  generation, and selected catalog mode to each connection.
- Enforced per-catalog and per-principal session limits plus per-catalog scan
  limits, with stable `42501` and `54001` errors and bounded aggregate metrics.
- Kept object-store credentials, locations, principal verifiers, and catalog
  IDs out of default metric labels and redacted CLI config output.

## Verification

```bash
cargo fmt --all -- --check
cargo test -p rocklake-router
cargo test -p rocklake-pgwire
cargo test --workspace
```

Storage-byte and object-count quotas remain report-only, and request-rate,
writer-transaction, administrative-job, and open-handle quotas remain reserved
for the measured enforcement work in a later release. There is no remote policy
management API or cross-catalog transaction support.
