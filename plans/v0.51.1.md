# v0.51.1 plan: telemetry correctness

## Scope

Fix metric semantics, request timing, request identity, and the minimum seams
needed by the later lifecycle patches. Do not change admission, idle timeout,
shutdown, or high-cardinality catalog scans in this patch.

## Outcomes

- Prometheus histogram output has monotonic buckets, an `+Inf` bucket equal to
  count, and a non-negative sum.
- Whole-request timing starts before classification and includes catalog work,
  executor work, response encoding, delivery, and completion.
- Telemetry separates admission, classification, execution, response delivery,
  time to first delivered row, and total request duration.
- Each simple or extended query has a `query_id`. A connection keeps its
  `connection_id` for its socket lifetime.
- The query ID reaches classification, catalog operations, errors, slow logs,
  and object-store spans.
- Connection close reports a debug lifecycle event instead of a slow operation.
- The root `COMPATIBILITY.md` exists before later public metric and configuration
  changes land.

## Implementation choices

Keep one cumulative histogram invariant. Either the counters or the renderer
may accumulate buckets, but both must not do so. Parse the Prometheus text in
tests instead of asserting one serialized bucket string.

Introduce only the request context, server limits, and response observation
state needed by these outcomes. Keep the later v0.53 ownership split out of
this patch.

Record time to the first row delivered to the client. Do not use a response
wrapper timestamp if it can occur before the first row reaches the socket.

## Black-box checks

| Scenario | Setup | Expected result |
|---|---|---|
| Histogram exposition | Run queries that populate several duration buckets. | Parsed buckets are monotonic and `+Inf` equals count. |
| Full request timing | Run a query with catalog and executor work. | Total duration exceeds each included phase and includes both work types. |
| Query correlation | Run simple and extended queries on one connection. | Each query has a unique ID and the connection ID stays constant. |
| First-row timing | Run a multi-row result through a slow client. | First-row timing precedes total request duration and reflects first delivery. |
| Healthy connection close | Keep a connection idle, then close it. | The close appears as a lifecycle event, not a slow query. |
| Upgrade compatibility | Create and write a catalog with the previous supported release. | The current release opens, reads, writes, and reopens it. |

## Exit conditions

Run the focused PG-wire observability tests, the compatibility manifest check,
and the existing release certification suite. Review the emitted metric names
against `COMPATIBILITY.md` before merging.
