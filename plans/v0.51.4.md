# v0.51.4 plan: client and operator ergonomics

## Scope

Reduce variation in the supported binary path and the preview Rust read APIs.
Keep old CLI spellings as hidden or deprecated aliases for at least two minor
releases.

## Outcomes

- Writer-backed, read-only, asynchronous, and synchronous readers share one
  read model for schemas, tables, snapshots, and data-file traversal.
- A read-only scan does not hold a mutable catalog lock after it creates its
  snapshot-bound reader.
- Snapshot access reports lock or storage errors instead of treating contention
  as a missing snapshot.
- The support matrix labels the binary, PG-wire, and DuckDB DuckLake path as
  Supported; Rust and DataFusion as Preview; and unmaintained bindings as
  Experimental.
- Release binaries are the primary README installation path.
- `doctor`, `serve`, `status`, `catalog`, and `debug` have distinct jobs while
  existing scripts continue to work.
- A new user can install, run a first query, and use the documented backup,
  restore, diagnosis, capacity, and upgrade paths without internal notes.

## Operator-task checks

| Task | Starting point | Expected result |
|---|---|---|
| First query | README and a release binary | The user installs RockLake, runs `doctor` and `serve`, and completes a DuckDB query. |
| Bad credentials | A failing configuration | `doctor` identifies the credential or connectivity problem. |
| Backup and restore | The operations guide | The operator creates a backup and restores it into a new catalog. |
| Capacity rejection | A documented overload error and metrics endpoint | The operator identifies the capacity limit and its current usage. |
| Upgrade | The upgrade guide and a previous supported release | The operator upgrades without internal documentation. |

## Exit conditions

Test the command aliases, generated DuckDB `ATTACH` syntax, redacted startup
output, checksum instructions, and the operator tasks above. Update the support
matrix and the compatibility migration notes in the same release.
